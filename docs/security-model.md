# Security Model

The update system must not activate downloaded content unless integrity and authenticity checks pass.

Planned safeguards:

- SHA256 checksums for every downloaded artifact.
- Manifest signatures generated by the CLI with a private key.
- Public key verification inside the Flutter app.
- Staging directories for incomplete downloads.
- Rejection of path traversal entries inside patch archives.
- Explicit rollback instead of silent downgrades.

The backend should not need access to the private signing key. The CLI should sign manifests before upload, and the app should verify them before install or activation.

Pre-1.0 releases are experimental and should not be used for production update distribution.
